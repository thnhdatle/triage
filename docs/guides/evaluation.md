# Evaluation

Measure how much strong-model quality a routing strategy keeps for the cost it saves.

`triage eval` runs the real pipeline of a route in your configuration on a dataset.

## Datasets

Use your own JSONL dataset, or the project's benchmark sets (GSM8K, MMLU and published GPT-4 / Mixtral labels):

```sh
scripts/fetch_eval_data.sh      # into ~/.cache/rayld/triage/eval/data
```

Sets and prompt templates are described in [eval/README.md](../../eval/README.md).
Example configurations: `eval/live.yaml` (live, LM Studio pair), `eval/labels-mmlu.yaml` (MMLU labels)
and `eval/labels-gsm8k.yaml` (GSM8K labels). `make eval` runs all three in about 10 minutes.

## Run it

```sh
triage eval --config eval.yaml [--out DIR]   # default out/eval/<UTC timestamp>/
```

The summary table is also printed. This example makes no model calls:

```yaml
# eval.yaml
mode: labels                           # live | labels
config: deploy/config.quickstart.yaml  # the Triage configuration
route: triage-auto                     # the route to evaluate
dataset: { jsonl: dataset.jsonl }      # or sets: [eval/sets/....txt]
strategies: [random, length]
bootstrap: { resamples: 10000, seed: 7 }
```

```jsonl
{"id": "q1", "prompt": "What is 2+2?", "weak_correct": true, "strong_correct": true}
{"id": "q2", "prompt": "Prove that the square root of 2 is irrational.", "weak_correct": false, "strong_correct": true}
```

## Dataset format

One JSON object per line.

| Field | Meaning |
|---|---|
| `id` | item id; default the line number |
| `messages` | OpenAI-shaped messages (text parts only) |
| `prompt` | one user message, if no `messages` |
| `reference` | expected answer (live mode) |
| `scorer` | how to judge the answer; default `exact` |
| `weak_correct`, `strong_correct` | booleans; required in labels mode |

| `scorer` | Correct when |
|---|---|
| `exact` | equals `reference`, whitespace trimmed |
| `regex` | `reference` regex matches |
| `numeric` (same as `gsm8k`) | final numbers match |
| `mmlu` | the chosen letter matches |

## Item sets

```yaml
dataset:
  sets: [eval/sets/live_cal.txt, eval/sets/live_eval.txt]     # item-id files
  prompts: eval/prompts/                       # live mode: gsm8k.txt and mmlu.txt
  data_dir: ~/.cache/rayld/triage/eval/data    # default <cache_dir>/data
  labels: { weak: mistralai/Mixtral-8x7B-Instruct-v0.1, strong: gpt-4-1106-preview }  # labels mode
```

A set file has one id per line: `gsm8k/test:<row>`, `gsm8k/test:*` or
`mmlu/test:<subject>:<row>`. `#` starts a comment. Calibration items are left out of the
evaluated items.

## Modes

### `labels`

Correctness comes from the dataset. No model is called and costs are 0.

### `live`

Answers are generated by two targets. `provider` is a key of the Triage configuration.

```yaml
mode: live
config: triage.yaml
route: triage-auto
dataset: { jsonl: dataset.jsonl }
targets:
  weak:   { provider: lmstudio, model: qwen/qwen3-vl-4b, pricing: { input_per_mtok: 0, output_per_mtok: 0 } }
  strong: { provider: openai,   model: gpt-5,            pricing: { input_per_mtok: 1.25, output_per_mtok: 10.0 } }
generation: { temperature: 0, seed: 7, max_tokens: 1024 }
strategies: [random, length, bert]
cache_dir: ~/.cache/rayld/triage/eval
```

Answers are cached in `cache_dir`, so a second run makes no model calls. A strategy that
cannot be built is shown as "not measured".

**`mf` sends the text of every item to the embedding provider**
([privacy.md](privacy.md#mf-egress)).

## Threshold

By default each strategy uses the route's `threshold`. To calibrate it instead:

```yaml
threshold_rule: { calibration: eval/sets/live_cal.txt, min_accuracy_of_all_strong: 0.96 }
```

This picks the threshold with the fewest strong calls that keeps 96% of all-strong accuracy.
Keep calibration and evaluation sets disjoint.

## Results

A run writes three files:

| File | Contents |
|---|---|
| `results.csv` | one row per strategy and item |
| `curve.csv` | one row per strategy and threshold (the cost-quality plot) |
| `summary.md` | one row per strategy, references and sweep tables |

```text
strategy,item_id,score,tier,weak_correct,strong_correct,correct,cost_usd
strategy,threshold,strong_ratio,accuracy,accuracy_ci_lo,accuracy_ci_hi,cost_usd,random_accuracy,pgr,chosen
```

Summary columns:

| Column | Meaning |
|---|---|
| threshold | route's or calibrated |
| strong calls | share sent to strong |
| accuracy (95% CI) | share answered correctly |
| random at same ratio | expected random-router accuracy |
| cost USD (95% CI) | total cost |
| cost vs all-strong | cost relative to all-strong |
| APGR (95% CI) | average performance gap recovered |

APGR: higher is better, random is about 0.5. Confidence intervals are wide for small
datasets; a few dozen items say little.

## Eval configuration keys

| Key | Default | Description |
|---|---|---|
| `mode` | required | `live` or `labels` |
| `config` | required | Triage configuration path |
| `route` | required | route to evaluate |
| `dataset.jsonl` | one of the two | JSONL dataset |
| `dataset.sets` | one of the two | item-id set files |
| `dataset.prompts` | required with `sets` in `live` | prompt template directory |
| `dataset.data_dir` | `<cache_dir>/data` | benchmark data |
| `dataset.labels.weak`, `.strong` | required with `sets` in `labels` | label file columns |
| `targets.weak`, `targets.strong` | required in `live` | `provider`, `model`, `pricing` |
| `generation.temperature`, `.seed`, `.max_tokens` | unset | generation settings (`max_tokens` 0 = not sent) |
| `strategies` | required | e.g. `random`, `length`, `bert`, `mf`, `none` |
| `threshold_rule.calibration` | unset | item-id file or JSONL |
| `threshold_rule.min_accuracy_of_all_strong` | `0.96` | share of all-strong accuracy to keep |
| `bootstrap.resamples` | `10000` | bootstrap resamples |
| `bootstrap.seed` | `0` | bootstrap seed |
| `cache_dir` | `~/.cache/rayld/triage/eval` | answer cache |
| `out_dir` | `out/eval/<timestamp>` | results directory |

Unknown keys are errors.
